# ai_hw_week5
# 個人 Dashboard Web App 規格書

## 一、專案名稱

**個人待辦事項與進度管理 Dashboard**

---

## 二、專案動機

平常在處理課業、專題或生活中的事情時，常常會有很多不同的待辦事項需要記錄。如果只使用紙本或單純的記事方式，容易忘記截止日期，也不容易知道目前還有多少事情沒有完成。

因此，我想製作一個簡單的個人 Dashboard，將待辦事項、完成進度與提醒功能集中在同一個網站中，讓使用者可以快速了解目前的工作狀況。

這個網站主要希望做到「新增待辦事項、追蹤完成進度、查看即將到期事項」三個功能。

---

# 三、網站目標

本網站希望提供一個簡單、容易操作的個人工作管理工具。

主要功能包括：

1. 新增個人待辦事項
2. 查看目前所有待辦事項
3. 設定待辦事項的截止日期
4. 設定待辦事項的優先程度
5. 設定每個待辦事項的完成進度
6. 將待辦事項標記為完成
7. 查看整體完成進度
8. 查看即將到期或已逾期的事項
9. 使用 LocalStorage 儲存資料
10. 關閉網頁後重新開啟，資料仍然可以保留

---

# 四、網站架構

網站主要分成三個頁面：

### 1. Dashboard 首頁

主要用來查看整體工作狀況。

### 2. 待辦事項頁面

主要用來新增及管理待辦事項。

### 3. 提醒頁面

主要用來查看即將到期、今天到期以及已逾期的待辦事項。

---

# 五、Dashboard 首頁

首頁是使用者開啟網站後看到的主要畫面。

## 5.1 統計資訊

首頁上方顯示目前的工作統計，例如：

* 全部待辦事項數量
* 已完成數量
* 未完成數量
* 整體完成率

例如：

> 全部待辦：10
> 已完成：6
> 未完成：4
> 完成率：60%

---

## 5.2 整體完成進度

使用進度條呈現目前所有待辦事項的完成狀況。

例如：

> 整體完成進度
> ██████░░░░ 60%

完成率會根據目前已完成的待辦事項自動計算。

---

## 5.3 待辦事項預覽

Dashboard 顯示部分重要的待辦事項，讓使用者不用進入待辦事項頁面就可以快速查看目前的工作。

每個事項可以顯示：

* 事項名稱
* 截止日期
* 優先程度
* 完成進度
* 完成狀態

---

## 5.4 快速操作

Dashboard 提供「新增待辦事項」按鈕。

使用者按下後，可以直接進入新增待辦事項的功能。

---

# 六、待辦事項頁面

這個頁面是網站最主要的操作區域。

## 6.1 新增待辦事項

使用者可以新增一筆待辦事項。

新增時可以輸入：

### 事項名稱

例如：

> 完成 Web App 作業

### 事項說明

可以輸入比較詳細的內容。

例如：

> 完成規格書、網站製作與 GitHub Pages 部署。

### 截止日期

使用日期選擇器設定截止日期。

### 優先程度

提供三種選擇：

* 高
* 中
* 低

使用不同顏色或標籤區分優先程度。

### 完成進度

使用者可以設定目前的完成百分比，例如：

> 0% ～ 100%

---

# 七、待辦事項管理

新增待辦事項後，會以卡片或列表方式顯示。

每一筆待辦事項需要顯示：

* 事項名稱
* 事項說明
* 截止日期
* 優先程度
* 完成進度
* 完成狀態

---

## 7.1 修改待辦事項

使用者可以修改已建立的待辦事項。

可以修改：

* 事項名稱
* 事項說明
* 截止日期
* 優先程度
* 完成進度

---

## 7.2 完成待辦事項

每個待辦事項提供「完成」功能。

使用者完成工作後，可以將該事項標記為完成。

標記完成後：

* 完成進度變成 100%
* 顯示完成狀態
* Dashboard 的完成數量會自動更新
* Dashboard 的整體完成率會自動更新

---

## 7.3 刪除待辦事項

使用者可以刪除不需要的待辦事項。

刪除後，Dashboard 的統計資料也要同步更新。

---

# 八、提醒頁面

提醒頁面主要用來協助使用者注意重要的待辦事項。

網站不需要使用瀏覽器的系統通知，而是直接在網站內提供提醒資訊。

---

## 8.1 已逾期

如果待辦事項的截止日期已經過去，而且尚未完成，顯示在「已逾期」區域。

例如：

> 🔴 已逾期
> 完成 Web App 作業
> 截止日期：10/19

---

## 8.2 今天到期

如果待辦事項的截止日期是今天，顯示在「今天到期」區域。

例如：

> 🟠 今天到期
> 完成報告
> 截止日期：今天

---

## 8.3 即將到期

如果待辦事項即將到期，顯示在「即將到期」區域。

例如：

> 🟡 即將到期
> 完成專題進度
> 截止日期：10/12

---

## 8.4 已完成事項

已經完成的待辦事項不需要出現在未完成提醒區域中。

這樣可以避免使用者看到已經完成的工作而產生混亂。

---

# 九、資料儲存

本網站使用瀏覽器的 **LocalStorage** 儲存資料。

不使用：

* MySQL
* Firebase
* 後端資料庫
* 其他外部資料庫

待辦事項會直接儲存在使用者自己的瀏覽器中。

---

## 9.1 資料保存

使用者新增待辦事項後，資料會自動儲存。

即使使用者：

* 重新整理網頁
* 關閉瀏覽器
* 重新開啟網站

原本的待辦事項仍然可以保留。

---

## 9.2 即時更新

當使用者：

* 新增事項
* 修改事項
* 完成事項
* 刪除事項

Dashboard、完成率與提醒頁面的內容都需要同步更新。

---

# 十、網站介面設計

整體採用**簡單、乾淨、容易閱讀的風格**。

不需要過度複雜的動畫或華麗設計。

## 10.1 介面方向

使用：

* 簡潔的卡片
* 清楚的按鈕
* 簡單的圖示
* 清楚的文字
* 進度條
* 優先程度標籤

讓使用者可以快速理解目前的工作狀況。

---

## 10.2 導覽列

網站提供簡單的導覽功能：

> 🏠 Dashboard
> 📝 待辦事項
> 🔔 提醒

使用者可以在三個頁面之間切換。

---

# 十一、互動功能

本網站必須具有實際可以操作的互動功能，而不是只有靜態文字。

主要互動功能包括：

1. 新增待辦事項
2. 修改待辦事項
3. 刪除待辦事項
4. 修改完成進度
5. 將事項標記為完成
6. 自動計算完成率
7. 自動更新 Dashboard 統計數字
8. 根據截止日期自動分類提醒
9. LocalStorage 自動儲存資料
10. 重新整理後保留資料
11. Dashboard 與提醒頁面即時更新

---

# 十二、技術規格

本網站最後需要整理成單一：

`index.html`

檔案。

CSS 與 JavaScript 直接寫在 HTML 裡，不另外建立：

* `style.css`
* `script.js`

網站不需要後端伺服器。

主要使用：

* HTML
* CSS
* JavaScript
* LocalStorage

完成網站。

---

# 十三、GitHub Pages

完成網站後，將 `index.html` 上傳至 GitHub Repository。

再透過 **GitHub Pages** 將網站公開，讓其他人可以透過網址直接開啟網站。

最終成果需要可以：

1. 正常開啟
2. 正常新增待辦事項
3. 正常修改及刪除事項
4. 正常修改完成進度
5. 正常顯示完成率
6. 正常顯示提醒
7. 重新整理後資料仍然存在

# 十五、預期成果

完成後，希望這個網站可以成為一個簡單的個人工作管理工具。

使用者可以透過 Dashboard 快速掌握：

> **「我現在有多少事情要做、完成多少、哪些事情快到期。」**

同時透過待辦事項頁面進行工作管理，再利用提醒頁面避免忘記重要工作。

本專案的重點不是製作複雜的系統，而是利用 Vibe Coding 與 AI 協助，把原本的想法轉換成一個真正可以操作的 Web App。
